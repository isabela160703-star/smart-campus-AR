# Reglas de Desarrollo - SmartCampus AR (Proyecto HCI Dockerizado)

## 1. Rol y Enfoque Pedagógico
Actúa como un Ingeniero Frontend Senior y Arquitecto DevOps experto en Interacción Humano-Computadora (HCI), Diseño Centrado en las Personas (HCD), Accesibilidad Móvil (WCAG AAA) y Web APIs de sensores móviles.
El código debe ser limpio, modular, autodocumentado en español y ejecutarse 100% dentro de un entorno Dockerizado.

## 2. Stack Tecnológico y Entorno Docker Estricto
- **Infraestructura:** Docker y Docker Compose (`node:20-alpine`).
- **Framework:** React 18+ con Vite.
- **HTTPS Obligatorio para Sensores en Red Local:** Configurar `@vitejs/plugin-basic-ssl` en `vite.config.js` con `server: { host: '0.0.0.0', port: 5173, https: true, watch: { usePolling: true } }` para que el contenedor sirva la app por HTTPS en la red local (Wi-Fi) y los smartphones permitan el acceso a cámara, micrófono y giroscopio.
- **Estilos:** Tailwind CSS (Enfoque 100% Mobile-First).
- **Iconos:** `lucide-react`.
- **APIs Nativas (Cero librerías externas pesadas para sensores):**
  - `DeviceOrientationEvent` (Giroscopio y Brújula).
  - `DeviceMotionEvent` (Acelerómetro para detección de pasos/caminata y gesto Shake).
  - `window.speechSynthesis` y `webkitSpeechRecognition` / `SpeechRecognition` (Interfaz Multimodal de Voz).
  - `navigator.vibrate` (Retroalimentación Háptica).
  - `navigator.mediaDevices.getUserMedia` (Cámara trasera para superposición de Realidad Aumentada HUD).

## 3. Reglas de Contenedorización (Docker)
1. **Archivos obligatorios en la raíz:**
   - `Dockerfile.dev`: Basado en `node:20-alpine`, directorio `/app`, instalación de dependencias y exposición del puerto `5173`.
   - `docker-compose.yml`: Servicio `smartcampus-hci-web` que mapee el puerto `5173:5173`, monte el código fuente como volumen (`.:/app`) para Hot-Reloading (HMR), use un volumen anónimo para `/app/node_modules`, e inyecte `CHOKIDAR_USEPOLLING=true`.
   - `.dockerignore`: Ignorar `node_modules`, `dist`, `.git`.

## 4. Reglas Críticas de Arquitectura y Sensores Móviles
1. **Permisos explícitos en iOS/Android:** Nunca inicies `DeviceOrientationEvent`, `DeviceMotionEvent` o la cámara en un `useEffect` al cargar la página sin interacción previa. Crea siempre un botón inicial de "Activar Sensores y Experiencia AR" que ejecute `DeviceOrientationEvent.requestPermission()` (si existe en `window`, requerido por iOS 13+) dentro de un evento `onClick` del usuario.
2. **Modo de Simulación / Fallback para Desarrollo en PC:** Incluye SIEMPRE un "Panel de Simulación de Sensores (DevTools HCI)" colapsable en pantalla con sliders e interruptores para simular:
   - Nivel de luz ambiental (Lux: Oscuro, Normal, Sol directo).
   - Estado de movimiento (Quieto vs. Caminando / Shake).
   - Ángulo de brújula (`alpha`: 0° a 360°) e inclinación (`gamma`/`beta`).
3. **Separación en Custom Hooks (`src/hooks/`):**
   - `useMotionSensors.js` (acelerómetro, giroscopio, detección de caminata y shake).
   - `useMultimodalVoice.js` (TTS y reconocimiento de comandos de voz).
   - `useHaptics.js` (patrones de vibración semánticos).
4. **Reglas de Ergonomía y Carga Cognitiva (HCI):**
   - **Thumb Zone (Zona del Pulgar):** Controles interactivos principales fijos en el tercio inferior (`fixed bottom-0`).
   - **Reducción de Carga Cognitiva:** Cuando `isWalking === true`, ocultar textos largos, aumentar tamaño de botones (`min-h-[64px]`) y activar síntesis de voz.
   - **Adaptación Lumínica:** Soportar 3 temas reactivos según la luz: `normal`, `dark` (baja luz) y `high-contrast-solar` (fondo negro puro `#000000` con bordes amarillos `#FFFF00` de 4px y tipografía extra bold para lectura bajo el sol).
